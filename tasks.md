## Анализ (2026-09-13)

**Как мерил.** iPhone 12 Pro — вьюпорт **390×844 CSS px** (DPR 3). Главная future-step.ru открыта в iframe шириной 390px,
размеры сняты через `getBoundingClientRect`/`getComputedStyle`. Все правки ниже проверены там же инъекцией CSS
на ширинах 320–430px. `1rem = 19.2px` (`html { font-size: 120% }`).

### Откуда 208px — три слоя отступов

1. **Мобильный боковой отступ не работает вообще.** `theme.scss:1627–1652` переопределяет
   `--wp--style--root--padding-*` на `:root`, но WordPress объявляет эти переменные на `body`
   (`global-styles-inline-css`: `body{--wp--style--root--padding-left:2.5rem}`). Значение на `body` перекрывает
   унаследованное от `:root`, поэтому у `<main>` на телефоне **48px** с каждой стороны вместо задуманных 19.2px.
   По той же причине не работает и планшетный `2rem` (768–1199px). Переопределения размеров шрифта
   (`--wp--preset--font-size--xxl/xxxl`) в том же блоке работают: ядро объявляет их на `:root`.
2. **Паддинг ядра у групп с фоном.** `wp-block-group-theme-inline-css` задаёт
   `:where(.wp-block-group.has-background) { padding: 1.25em 2.375em }`, это **42.75px** по бокам.
   Такой паддинг есть у четырёх групп темы: две обёртки шапки (`header-nav.php:80`, `:111`), обёртка подвала
   (`footer-columns.php:35`) и серая карточка вузов (`alumni-strip.php:31`).
3. **Десктопные паддинги карточек hero.** У `.fs-hero-dirs` 2.5rem (48px), у `.fs-hero-form` 2rem (38.4px).

Карточка вузов: 390 − 2×48 − 2×42.75 − 2 (рамка) = **206.5px**. Подвал: 390 − 2×42.75 − 2×48 = **208.5px**.
Отсюда те самые «208». 304 = 208 + 96, то есть как раз без паддинга `<main>`.

## План исправления

**Брейкпоинты.** Отступы, карточки, статистика и логотипы — `max-width: 767px`: это существующий мобильный
брейкпоинт темы, на нём сетки уже в одну колонку. Шапка и поля формы — `max-width: 600px`: там шапка

### Шаг 1. Боковой отступ контента (п. 2) — `src/scss/theme.scss:1621–1652`

Перенести переменные отступа с `:root` на `.wp-site-blocks`. Это потомок `body`, поэтому его значение
выигрывает независимо от порядка CSS (WP Rocket может склеивать и переставлять стили). Переопределения
`font-size` оставить на `:root`. Поправить устаревший комментарий («60px/32px/20px»).

Правило для планшетов тоже включаем (решено 2026-09-13): на 768–1199px отступ станет `2rem` (38.4px) вместо нынешних 48px.

```scss

	.wp-site-blocks {
		--wp--style--root--padding-left: 2rem;
		--wp--style--root--padding-right: 2rem;
	}
}

@media ( max-width: 767px ) {
	.wp-site-blocks {
		--wp--style--root--padding-left: 1rem;   // 19.2px
		--wp--style--root--padding-right: 1rem;

	}
}
```

# Редактирование контента из админки (2026-09-13)

**Зачем.** На проде страницы открываются в классическом редакторе (WPBakery отключает блочный), шаблоны и части сайта
в «Редактировать сайт» не сохранялись. Секции главной и страниц направлений правятся только в коде. Сохранение шаблона
главной в «Редактировать сайт» отвязывает его от темы: правки вёрстки из кода перестают доходить, а кнопка «Записаться»
застывает. Поэтому часто меняемый контент переносим в записи админки с полями, а разметку по-прежнему выводит тема.

## Этап 1 — «Выпускники» и «Вузы» (сделано, не выпущено)

- `inc/Showcase.php`: подключение модулей и доступ к ним из паттернов (`FS_LMS_Theme_Showcase::alumni()` / `::universities()`).
- `inc/Showcase/Showcase_Type.php`: общая механика. Закрытый для фронта тип записи, классический экран
  (`show_in_rest => false`), изображение записи и «Порядок». Слайды берутся из опубликованных записей по порядку, затем
  по названию. В списке админки столбцы «Фото»/«Логотип» и «Порядок». При изменениях сбрасывается кэш главной в WP Rocket
  (`rocket_clean_home()`). Стартовые записи из прежнего содержимого паттернов заводятся один раз
