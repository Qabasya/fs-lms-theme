# FS LMS Theme

Блочная (FSE) WordPress-тема сайта future-step.ru для плагина `fs-lms`: своя
дизайн-система, кастомные Gutenberg-блоки и паттерны секций. Не путать с
`design-mockup/README.md` — там описан Claude Design хэндофф, использованный
как источник вёрстки/токенов, а не сама тема.

История работ и решений по фазам — [`tasks.md`](tasks.md).

## Как редактировать сайт

Всё, что часто меняется, правится в админке WordPress в разделах темы. Вёрстку
(как это выглядит) при этом выводит тема, поэтому ничего сломать нельзя —
меняются только тексты, картинки и порядок.

### Где что меняется

| Что на сайте | Где в админке |
|---|---|
| Карусель «Наши выпускники» на главной: фото, результат, имя, отзыв | **Выпускники** |
| Лента логотипов «Наши выпускники поступают» | **Вузы** |
| «Частые вопросы» на главной и разделы страницы «О нас» | **Вопросы** (поле «Где показывать») |
| Направления: список «Направления подготовки» и карточки курсов на главной, каталог «Курсы», первый экран страницы направления (текст слева от формы и факты под формой) | **Направления** |
| Телефон, почта, адрес, режим работы, куда приходят заявки, ссылки MAX/ВКонтакте/Карты/2ГИС | **Настройки сайта** → «Контакты», «Ссылки» |
| Факты под формой на главной («84 средний балл» и т.д.), плашка «2 часа / 800 ₽» в «Как устроены занятия» | **Настройки сайта** → «Цены и факты» |
| Пункты меню шапки | **Внешний вид → Редактор → Навигация → «Меню шапки»** |
| Секции «Как устроены занятия» и «Хочешь больше?» на конкретной странице направления | **Страницы → страница направления → «Изменить»**, вкладка «Текст» (правка HTML, см. ограничения ниже) |
| Заголовок страницы (например, «ИП Иванов Борис Олегович» на «О нас») | **Страницы → страница → «Изменить»**, поле заголовка |
| Всё остальное: вёрстка и цвета, «Сделаем вместе», формы, реквизиты ИП/ИНН/ОГРН, карта в подвале, вводный абзац «О нас» | Только в коде темы — через разработчика |

### Разделы «Выпускники», «Вузы», «Вопросы», «Направления»

Каждая запись — один выпускник, вуз, вопрос или направление.

- **Добавить** — «Добавить …» вверху списка. **Скрыть с сайта, не удаляя** —
  перевести запись в черновик. **Удалить** — в корзину.
- **Порядок** — поле «Порядок» справа на экране записи: меньше число — раньше в
  карусели, списке или аккордеоне. Стартовые записи стоят через 10 (10, 20, 30…),
  чтобы новую можно было вставить между ними (например, 15).
- **Картинки** — блок справа («Фото», «Логотип», «Картинка на главной»), у
  направлений ещё «Картинка в каталоге» в основной форме. Пока картинка не
  выбрана, показывается прежняя из темы.
  - Фото выпускника — квадратное, от 300×300.
  - Логотип вуза — PNG или SVG с прозрачным фоном, по высоте логотип 120px на
    компьютере и 80px на телефоне.
  - Направление на главной — 4 : 3 (например, 1920×1440), обрезается по краям.
  - Направление в каталоге «Курсы» — 2,4 : 1 (например, 1920×800), показывается
    целиком.
- **Ответ в «Вопросах»** — обычный визуальный редактор: абзацы, списки, ссылки,
  PDF через «Добавить медиафайл». «Открыт по умолчанию» — вопрос раскрыт при
  загрузке страницы.
- **Направления**:
  - «Ключ предмета» — слаг страницы предмета в плагине (`inf_ege`, `inf_oge`,
    `python`, `robo`); из него строится ссылка «Подробнее», по нему страница
    направления берёт свой первый экран.
  - «Цвет» — бейдж класса и фон первого экрана.
  - «Текст слева от формы» — абзацы разделяются пустой строкой; над текстом
    автоматически стоят класс и название.
  - Черновик прячет направление со всех списков, но первый экран его
    страницы продолжает работать.
- Сохранение сразу видно на сайте: кэш WP Rocket сбрасывается сам. Если
  изменений не видно — «WP Rocket → Очистить кэш» в верхней панели.

### «Настройки сайта»

Один экран, значения меняются на всех страницах сразу. Неверный адрес почты
или ссылка не сохраняются — остаётся прежнее значение, сверху появляется
предупреждение. Пустые значение и подпись факта — факт не показывается.

Плашка «Как устроены занятия» есть на главной и копией на каждой странице
направления. Значение из настроек показывается везде, где на странице стоит
прежнее значение («2 часа», «одно занятие», «800 ₽», «за час»). Если на
странице направления его поменяли вручную, там остаётся своё.

### Чего не делать

- **Не сохранять страницы, собранные темой, через WPBakery** (кнопки
  «Backend Editor» / «Frontend Editor»): страницы направлений, «О нас»,
  «Курсы», «Контакты». WPBakery оборачивает содержимое в свои шорткоды и
  выбрасывает секции темы — так 13 сентября 2026 со страницы «Робототехника»
  пропали первый экран, форма и «Сделаем вместе».
- **На страницах направлений — только вкладка «Текст»** классического
  редактора и не трогать строки вида `<!-- wp:… -->`: вкладка «Визуально»
  ломает разметку блоков.
- **Не сохранять главную, шапку и подвал в «Внешний вид → Редактор»**
  (Site Editor). После первого сохранения шаблон копируется в базу и
  отвязывается от темы: исправления вёрстки из обновлений темы до него больше не
  доходят, кнопка «Записаться» в шапке перестаёт вести к форме текущей
  страницы. Вернуть — у шаблона «⋮ → Сбросить».

### Если страница направления сломалась

Очистить содержимое страницы (вкладка «Текст» → выделить всё → удалить →
«Обновить») и открыть её на сайте, оставаясь в админке: тема сама соберёт
страницу заново из стандартных секций. Либо восстановить прошлую редакцию:
«Редакции» в редакторе страницы.

### Обновление темы

Новые версии выходят на GitHub. Обновить — «Внешний вид → Темы» (или
«Консоль → Обновления»): у темы появляется «Доступна новая версия» с кнопкой
обновления. После обновления открыть любую страницу сайта — разовые переносы
данных (стартовые записи разделов и т.п.) выполняются на первом запросе.

## Контент из админки: как устроено

`inc/Showcase.php` подключает модули и отдаёт по одному экземпляру на тип:
`FS_LMS_Theme_Showcase::alumni()` / `::universities()` / `::questions()` /
`::directions()` / `::settings()`. Паттерны берут готовую разметку оттуда.

| Файл | Что |
|---|---|
| `inc/Showcase/Content_Type.php` | Абстрактная механика типа записи: регистрация (`public => false`, `show_in_rest => false` — классический экран, работает при WPBakery и Classic Editor), выборка опубликованных по «Порядку», стартовые записи, сортировка списка в админке, столбец «Порядок», сброс кэша WP Rocket |
| `inc/Showcase/Featured_Image.php` | Трейт: `<img>` изображения записи или заглушки темы, столбец-миниатюра |
| `inc/Showcase/Showcase_Type.php` | Карусели: трейт изображения + `slides_markup()` |
| `inc/Showcase/Alumni.php`, `Universities.php` | «Выпускники» (`fs_alumnus`, метабокс «Результат»/«Отзыв») и «Вузы» (`fs_university`) |
| `inc/Showcase/Questions.php` | «Вопросы» (`fs_question`): место показа, «открыт по умолчанию», фильтр списка; `faq_markup()` и `about_markup()` |
| `inc/Showcase/Directions.php` | «Направления» (`fs_direction`): поля карточек и первого экрана, `hero_list_markup()`, `course_cards_markup()`, `catalog_cards_markup()`, `subject_hero_markup( $key )`, `find( $key )` |
| `inc/Showcase/views/subject-hero.php` | Разметка первого экрана страницы направления (общая для всех, паттерны `subject-hero*.php` — обёртки) |
| `inc/Showcase/admin/media-field.js` | Выбор картинки из медиатеки в метабоксе (без сборки, попадает в релиз как есть) |
| `inc/Showcase/Site_Settings.php` | «Настройки сайта»: опция `fs_lms_theme_site_settings`, `get()`, `phone_href()`, `address_full()`/`address_short()`/`address_lines()`, `hero_stats()`; фильтр `render_block_core/paragraph` для плашки «Как устроены занятия» |
| `inc/Showcase/seeds/*.php` | Стартовые данные — собраны скриптами из прежних паттернов |

Принципы:

- **Разметка не меняется.** Слайды, карточки и пункты собираются в той же
  блочной разметке, что стояла в паттернах (`fs-lms/alumni-card`,
  `fs-lms/faq-item`, `fs-lms/course-card`, `fs-lms/catalog-card`, `wp:image`,
  `wp:group`), с комментариями блоков — ядро подключает стили блоков как
  раньше. Все значения экранируются (`esc_html`/`esc_url`/`esc_attr`,
  ответы вопросов — `wpautop( wp_kses_post() )`).
- **Стартовые записи** заводятся один раз на `init` (опция
  `fs_lms_theme_seeded_{post_type}`, ставится через `add_option()` до вставки —
  защита от двойного запуска) и только если записей этого типа ещё нет.
  Вставка — со снятым kses (хук срабатывает и у анонимного посетителя).
- **Нет записи** — секция не выводится; у первого экрана направления запасной
  вариант — стартовые данные темы.
- **Страницы с содержимым в базе** (направления) обновляются разовыми
  «раскладками» — `FS_LMS_THEME_SUBJECT_PAGES_LAYOUT` в `inc/SubjectPages.php`
  и `inc/ContentUpgrades.php`. Запись — через `wp_update_post( wp_slash() )`
  со снятым kses: без `wp_slash()` пропадают `-` в атрибутах блоков.

Добавить ещё один раздел: наследник `FS_LMS_Theme_Content_Type` (или
`FS_LMS_Theme_Showcase_Type` для карусели) с `post_type()`, `labels()`,
`menu_icon()`, `seed_items()` и методом разметки; зарегистрировать в
`inc/Showcase.php`; в паттерне вывести разметку вместо статичных блоков.

## Сборка

```bash
npm install
npm run build        # разработка: собирает assets/, пишет sourcemaps
npm run watch        # то же + пересобирает на каждое изменение src/
npm run build:prod   # прод: без sourcemaps (gulp build --production)
```

Сборка — gulp + webpack, по образцу плагина `fs-lms` (`gulpfile.js`), не
`@wordpress/scripts`. Результат пишется в `assets/` (гитигнорится, всегда
собирается заново из `src/`).

Линтеры:

```bash
npm run lint:js    # eslint src/js src/blocks
npm run lint:css   # stylelint src/scss src/blocks
```

Локальный стенд — `../docker-compose.yml` (WordPress на `:8080`, тема
смонтирована из репозитория, в контейнере `wp_app` есть `wp-cli`).

## Как добавить новый блок

1. Создать `src/blocks/<name>/{block.json,index.js,edit.js,save.js,style.scss}`
   по образцу существующего блока (например `src/blocks/stat-tile/`).
2. `block.json`: `apiVersion: 3`, `name: "fs-lms/<name>"`,
   `category: "fs-lms-cards"`, `textdomain: "fs-lms-theme"`.
3. Ничего не прописывать в `gulpfile.js`/`inc/Blocks.php` — оба находят блок
   через `glob` по файловой структуре сами.
4. `npm run build`, затем использовать блок в паттерне.

Подробнее — [`src/blocks/README.md`](src/blocks/README.md).

## Блоки (`src/blocks/`)

Кастомные Gutenberg-блоки, категория инсёртера `fs-lms-cards`. Каждый —
папка `src/blocks/<name>/`: `block.json` (атрибуты), `edit.js` (вид в
редакторе + инспектор), `save.js` (что сохраняется в разметку страницы),
`style.scss` (стили фронта+редактора).

| Блок | Что показывает | Где используется |
|---|---|---|
| `fs-lms/course-card` | Обложка, бейдж класса, название, описание, цена, кнопка — карточка курса | главная, из «Направлений» |
| `fs-lms/catalog-card` | Карточка каталога: обложка, класс, частота, описание, цена и пояснение, фильтр по классу | `/courses/`, из «Направлений» |
| `fs-lms/alumni-card` | Фото, баллы, имя, короткий отзыв выпускника | главная, из «Выпускников» |
| `fs-lms/faq-item` | Вопрос/ответ на нативном `<details>/<summary>` | главная, из «Вопросов» |
| `fs-lms/feature-card` | Иконка, заголовок, текст — карточка преимущества | «Сделаем вместе» |
| `fs-lms/teacher-card` | Фото, имя, роль, био | библиотечный |
| `fs-lms/testimonial-card` | Аватар/инициалы, имя, отзыв, рейтинг | библиотечный |
| `fs-lms/stat-tile` | Крупное число, подпись, пояснение | библиотечный |
| `fs-lms/cta-banner` | Заголовок, текст, 1–2 кнопки | библиотечный |

Разметку `course-card`, `catalog-card`, `alumni-card`, `faq-item` на сайте
собирает PHP из записей админки (`inc/Showcase/*`) — при изменении `save.js`
этих блоков нужно синхронно поправить соответствующий метод разметки.

## Как добавить новый паттерн

1. Новый файл `patterns/<slug>.php` с докблоком:
   ```php
   <?php
   /**
    * Title: Человекочитаемое название
    * Slug: fs-lms-theme/<slug>
    * Categories: fs-lms-sections
    * Keywords: слово, для, поиска, в, инсёртере
    */
   ?>
   <!-- сериализованная разметка блоков -->
   ```
2. WordPress регистрирует паттерн автоматически по докблоку.
3. Паттерн исполняется как PHP на каждом запросе (`ob_start()+include`), поэтому
   в нём можно выводить данные: `FS_LMS_Theme_Showcase::…`, `fs_lms_theme_url()`,
   `fs_lms_theme_subject_url()` вместо захардкоженных URL и текстов.

## Паттерны (`patterns/`)

Секции подключаются ссылкой `<!-- wp:pattern {"slug":"…"} /-->` из шаблона
(`templates/front-page.html`, `parts/*.html`) или из содержимого страницы. Ссылка
живая: правка файла паттерна сразу видна везде. Открытие в блочном редакторе
(в том числе «Внешний вид → Редактор») заменяет ссылку копией блоков, и после
сохранения правки файла до этого места больше не доходят.

| Паттерн | Секция | Данные |
|---|---|---|
| `header-nav` | Шапка: топбар, лого, меню, «Записаться», кабинет | телефон/почта — «Настройки сайта», меню — `wp_navigation` |
| `footer-columns` | Подвал: контакты, карта, реквизиты, копирайт | контакты — «Настройки сайта» |
| `hero` | Первый экран главной: список направлений, форма `#hero-form`, факты | «Направления», «Настройки сайта» |
| `alumni-carousel` | «Наши выпускники» | «Выпускники» |
| `alumni-strip` | «Наши выпускники поступают» — логотипы | «Вузы» |
| `features-grid` | «Сделаем вместе» | код |
| `courses-grid` | Карточки курсов на главной | «Направления» |
| `intensive-split` | «Как устроены занятия» на главной | плашка — «Настройки сайта» |
| `contact-section` | Форма `#signup` на главной | контакты — «Настройки сайта» |
| `faq` | «Частые вопросы» | «Вопросы» (главная) |
| `courses-catalog`, `courses-contact` | Страница `/courses/` | «Направления», «Настройки сайта» |
| `contacts-info` | Страница `/contacts/` | «Настройки сайта» |
| `about-header`, `about-accordion` | Страница `/about/` | «Настройки сайта», «Вопросы» («О нас») |
| `subject-hero`, `subject-hero-oge`, `subject-hero-python`, `subject-hero-robo` | Первый экран страницы направления | «Направления» (по ключу предмета) |

Страницы направлений (`/inf_ege/` и т.д.) создаёт плагин пустыми, при первом
открытии тема записывает в них набор секций (`inc/SubjectPages.php`): ссылки на
`subject-hero*`, `features-grid`, `subject-contact` и копию «Как устроены
занятия» (и «Хочешь больше?» у предметов с учебником и тренажёром).

## Формы и Yandex SmartCaptcha

В теме две рабочие лид-формы «оставьте контакты, перезвоним» —
`#hero-form` (паттерны `hero.php`/`subject-hero*`) и `#signup`
(`contact-section.php`/`subject-contact.php`/`courses-contact.php`). Это **не**
заявка на зачисление плагина `fs-lms` — своя лёгкая логика в теме,
`inc/Forms.php` + `src/js/forms.js`.

### Как это работает

1. Каждая форма — `<form data-fs-form>` в `wp:html` внутри паттерна.
   `src/js/forms.js` перехватывает `submit`, шлёт `fetch` на `admin-ajax.php`
   (`action=fs_theme_submit_form`) и показывает ответ в `.fs-form-message`.
2. Обработчик — `fs_lms_theme_handle_form_submit()` в `inc/Forms.php`: nonce →
   honeypot + HMAC-таймер → rate-limit по IP → капча (если настроена) →
   валидация имени/телефона → письмо через `wp_mail()` на адрес из «Настройки
   сайта → Куда приходят заявки с форм».
3. Honeypot — скрытое поле `fs_company`. HMAC-таймер — поле `fs_form_token`
   (`{timestamp}.{hmac}`, подписано `AUTH_KEY` или `FS_LMS_THEME_FORM_SALT`) —
   отсекает сабмит быстрее `FS_LMS_THEME_FORM_MIN_FILL_SECONDS` и токены старше
   часа. Метка и nonce берутся заново на первом фокусе в форме
   (`action=fs_theme_form_token`), поэтому кэш страниц формам не мешает.

### Капча

Капча опциональна: без ключей формы работают на honeypot+таймере+rate-limit.

1. Получить пару ключей Yandex SmartCaptcha в
   [Yandex Cloud](https://cloud.yandex.ru/services/smartcaptcha) для домена.
2. **Настройки → Формы** (`inc/SmartCaptcha.php`) — вписать Site key и Server key.
3. Дальше автоматически: контейнер `<div data-fs-captcha>` в формах, невидимый
   виджет на первом фокусе (`src/js/captcha.js`, скрипт Яндекса вставляется не
   через `wp_enqueue_script` — иначе WP Rocket отдаёт его со своего домена и
   iframe капчи открывает 404), проверка `smart-token` на сервере с таймаутом
   5 сек и fail-open. Без токена (капча не загрузилась) — общий лимит
   `FS_LMS_THEME_FORM_NO_CAPTCHA_LIMIT` заявок в час и пометка в письме.
4. Ключи темы независимы от капчи плагина `fs-lms`
   (`fs_lms_theme_captcha_site_key`/`fs_lms_theme_captcha_server_key`).

### Письмо, лимиты, новое поле

- Получатель — «Настройки сайта»; тема письма — `FS_LMS_THEME_FORM_MAIL_SUBJECT`.
- Лимиты — константы `FS_LMS_THEME_FORM_*` в начале `inc/Forms.php`.
- Новое поле — `<input>` с нужным `name` в разметке формы **и** чтение
  (`sanitize_text_field` + строка в `$lines`) в
  `fs_lms_theme_handle_form_submit()`. Разметка первого экрана направлений —
  `inc/Showcase/views/subject-hero.php`.
- Обязательные служебные поля любой формы: `form_id`, `fs_form_token`,
  honeypot, `.fs-form-message`, сам `<form data-fs-form>`.

## Где искать токены

Единственный источник дизайн-токенов — `fs-lms` plugin
`src/scss/frontend/_variables.scss` + `src/scss/shared/_tokens.scss`.
`theme.json` — их синхронизированное зеркало (цвета, шрифты, spacing,
radius, тени, брейкпоинт сеток `960px` = `$bp-tablet` плагина). Шрифтовая шкала
темы — в шапке `src/scss/theme.scss`.

## Как сделать релиз

Сборка релиза — GitHub Actions (`.github/workflows/release.yml`), запускается
пушем тега `vX.Y.Z`: lint → сверка версии → `npm run build:prod` → ZIP по
`.distignore` → GitHub Release.

1. Поднять версию в `style.css` (`Version:`) **и** в `package.json` /
   `package-lock.json` — workflow сверяет тег с обоими:

   ```bash
   npm version 1.5.0 --no-git-tag-version   # package.json + package-lock.json
   # style.css: Version: 1.5.0
   git add style.css package.json package-lock.json
   git commit -m "версия 1.5.0"
   ```

2. Запушить коммит и аннотированный тег:

   ```bash
   git push
   git tag -a v1.5.0 -m "релизная версия"
   git push origin v1.5.0
   ```

3. Дальше — Actions: lint, сверка версии, сборка, `fs-lms-theme-1.5.0.zip`,
   публикация Release. На сайте обновление появится в «Внешний вид → Темы».
4. Если релиз упал на гейте — поправить, закоммитить и либо перевыпустить тег
   (`git tag -d vX.Y.Z && git push origin :vX.Y.Z`, затем шаг 2), либо взять
   следующий номер версии.
